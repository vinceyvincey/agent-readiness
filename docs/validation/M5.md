# M5 - Dogfooding + distribution + language-aware engine

Date: 2026-08-26. Closed M5.

## Dogfooding surfaced a real bug (the value of dogfooding)
Running the readiness tool on a genuinely well-structured Python repo (pdf-mcp) scored it **L0/51.7** - too low, and wrong: it has pytest, pre-commit, CI, full docs. Root cause: the engine's checks were **JS/Python-toolchain-biased**.

### Fixed (engine now language-aware)
- P2.3 run-test one-liner: +pytest/pyproject detection.
- P2.4 coverage: +[tool.coverage]/fail_under in pyproject/tox.
- P2.6 fast path: +python marker.
- P3.1 lockfiles: +Pipfile.lock/requirements.lock.
- P3.3 root scripts: +pyproject console_scripts.
- P3.6 dev/prod split: +poetry group dev.

### Result
pdf-mcp: 51.7 -> **59** (P2 33.3->66.7, P3 40->80, P8 60). Language bias materially reduced.

## Fix-loop demonstration (M5 verify line)
On a copy of pdf-mcp, the tool's --fix generated a real AGENTS.md. Applying only that file took the copy **59 -> 67**, lifting P1 0% -> 60%. Directly satisfies 'target repo score improves after --fix'.
